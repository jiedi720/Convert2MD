# Markdown 格式转换工具 - 需求说明文档

## 1. 项目概述

### 1.1 总体目标
本项目旨在开发一款基于 Python 的桌面应用程序，能够将常见的文档格式（PDF、Word、TXT 等）统一转换为 Markdown（.md）格式。工具需具备直观的图形用户界面（GUI），支持单文件及批量转换，并遵循高内聚、低耦合的软件设计原则，确保系统的可扩展性与可维护性。

### 1.2 设计理念
- **模块化架构**：采用清晰的三层架构（界面层、功能层、启动入口），各层职责明确，降低模块间依赖。
- **可扩展性**：为未来新增文档格式支持、插件化功能、CLI 支持等预留接口。
- **用户体验**：提供简洁易用的 GUI 界面，实时反馈转换进度与结果。
- **稳定性**：具备错误处理机制，对异常输入或转换失败情况有明确提示。

## 2. 工程结构与职责划分

### 2.1 项目整体结构
```
Convert2MD/
├── Convert2MD.py          # 程序启动入口
├── gui/                   # GUI 界面层
│   ├── __init__.py

├── functions/             # 功能层
│   ├── __init__.py
│   ├── converters/        # 转换器模块
│   │   ├── pdf_converter.py
│   │   ├── docx_converter.py
│   │   └── txt_converter.py
│   ├── utils/             # 辅助工具
│   │   └── file_helper.py
│   └── core.py            # 核心转换逻辑调度
└── requirements.txt       # 依赖声明
```

### 2.2 模块职责说明

#### 2.2.1 `gui/` 目录
- **职责**：负责所有用户界面相关逻辑。
- **具体功能**：
  - Tkinter 窗口初始化与布局管理。在打开桌面程序时，优化用户视觉体验，消除窗口启动时的"视觉闪烁"现象（即窗口先在左上角默认位置出现，随后瞬间移动到屏幕中央的突跳感）。该任务要求通过预先计算坐标并利用窗口撤回（Withdraw）机制，实现优雅的居中加载。
  - 文件选择按钮、拖拽区域、格式下拉框等 UI 组件的创建与样式设置。
  - 事件绑定（如"选择文件"、"开始转换"按钮点击事件）。
  - 转换进度条、状态栏、消息提示等交互反馈。

#### 2.2.2 `functions/` 目录
- **职责**：封装所有文档解析与 Markdown 转换的核心业务逻辑。
- **具体功能**：
  - 提供独立的转换器模块，分别处理 PDF、Word、TXT 等格式。
  - 实现文本提取、段落结构保持、基础格式（粗体、斜体、列表）映射到 Markdown 语法。
  - 包含文件类型自动识别与验证功能。
  - 提供批量处理接口，支持多文件并发或顺序转换。

#### 2.2.3 根目录 `Convert2MD.py`
- **职责**：程序的唯一启动点。
- **具体功能**：
  - 初始化并启动 GUI 界面。
  - 作为胶水层，将 GUI 的操作请求传递给 `functions` 模块，但自身不包含任何转换逻辑。

## 3. 核心功能模块说明

### 3.1 文档格式转换
- **PDF → Markdown**：从 PDF 文件中提取文本、标题、列表等元素，并转换为对应的 Markdown 语法。
- **Word (.docx) → Markdown**：解析 .docx 文件，提取文本、标题、列表等元素，并转换为对应的 Markdown 语法。
- **TXT → Markdown**：将纯文本文件按行或段落转换为 Markdown 格式，保留基本换行结构，智能识别标题、列表等元素，并转换为对应的 Markdown 语法。

### 3.2 批量文件处理
- 支持用户一次性选择多个文件进行转换。
- 提供进度监控，显示当前处理文件与总进度。
- 转换结果可统一输出到指定目录。

### 3.3 文件类型识别
- 自动根据文件扩展名判断输入文件类型。
- 对于无法识别的格式，应给出明确错误提示。

## 4. GUI 层交互能力

### 4.1 基础交互
- **文件选择**：支持通过按钮点击或文件拖拽方式选择待转换单个或多个文件，选择目录可以选择文件目录里所有的文件。
- **格式预览**：在转换前，可预览已选择的文件列表。
- **转换触发**：提供"开始转换"按钮，启动转换流程。
- **状态提示**：实时显示转换进度、成功/失败信息、错误日志等。

### 4.2 用户体验优化
- 界面响应迅速，避免因后台转换任务导致的卡顿。
- 提供"取消"或"停止"按钮，允许用户中断正在进行的批量任务。

## 5. 软件设计原则

### 5.1 高内聚、低耦合
- `gui` 模块专注于界面渲染与用户交互，不涉及文档解析。
- `functions` 模块独立于 GUI，可在无界面环境下作为库调用。
- `Convert2MD.py` 仅作为启动器，不承担业务逻辑。

### 5.2 可扩展性设计
- 转换器模块应设计为插件式结构，便于未来添加新格式支持（如 EPUB、HTML）。
- 核心调度模块应提供统一的接口，方便集成新的转换器。
- 预留日志系统、配置文件读取等模块的接入点。
